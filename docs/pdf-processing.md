# PDF 与文档分块

支持上传 PDF、DOCX、PPTX、Markdown、HTML、TXT 和 LaTeX。文档解析后会分成适合检索的段落，并保留来源信息，供问答时引用。

## 选择 PDF 解析方式

| 方式 | 配置 | 适用场景 |
| --- | --- | --- |
| MinerU 在线解析（默认） | `MINERU_ENABLED=true`，填写 `MINERU_API_TOKEN` | 扫描件、表格、多栏论文等复杂版面；PDF 会发送到 MinerU 服务 |
| 本地文字提取 | `MINERU_ENABLED=false` | 含可选中文字、结构较简单的 PDF；无需 MinerU 凭证 |

本地解析使用 pypdf，不具备 OCR 文字识别能力，也不保留原始字号和完整排版。扫描 PDF 请使用 MinerU 或先进行 OCR。多栏文字的读取顺序可能影响分块，复杂论文优先选择 MinerU。

PDF 必须包含至少一页且能够正常读取。需要输入密码的文件，请先解密再上传；空白页和扫描页会保留原页码。

## 准备分词文件

分块时需要计算文本的 token 数量，用来控制每段长度。API 模式使用约 17 MB 的 BGE-M3 分词文件，仅做文字切分和计数，不运行本地检索模型。

Docker 构建会自动下载该文件。本地 Python 开发时，在项目根目录运行一次：

```powershell
python backend/scripts/prepare_chunk_tokenizer.py
```

文件默认保存在 `backend/resources/tokenizers/bge-m3/tokenizer.json`，准备命令会校验下载内容。上传处理期间使用本地文件，不会临时下载。文件来源和许可见 [BGE-M3 分词文件声明](licenses/bge-m3-notice.md)。

### 可选：更换分词规则

默认 BGE-M3 模型无需调整。使用其他模型且需要与其分词方式一致时，同时配置：

| 配置 | 含义 |
| --- | --- |
| `CHUNK_TOKENIZER_PATH` | 分词 JSON 文件路径；相对路径从 `backend` 目录计算，Docker 中须填写容器内可读的路径 |
| `CHUNK_TOKENIZER_SHA256` | 该文件的 SHA-256 校验值 |

更换 API 模型名称不会自动更换分词文件，不同模型的 token 计数可能不同。修改分词规则后需重启后端，并重新处理需要使用新规则的资料。本地模型模式使用所配置模型的分词器。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 提示分词文件不存在 | 运行准备命令；使用自定义路径时检查文件是否可被后端读取 |
| 提示分词文件校验失败 | 核对自定义文件与校验值；默认文件损坏时先移走该文件，再运行准备命令 |
| PDF 无法读取或要求密码 | 检查文件能否正常打开，必要时重新导出或解密后上传 |
| 本地解析没有文字或无法形成有效段落 | 检查是否为扫描件或复杂版面，改用 MinerU 或先进行 OCR |
| MinerU 返回漏页或损坏图片 | 查看后端日志中的页码或资源错误，检查原文件和解析结果后重新处理 |
| 提示处理参数与已有记录不一致 | 确认当前解析与模型配置后重新处理该资料 |

评测用的 PDF 原文快照生成方式见 [测试与评测](evaluation.md)。
